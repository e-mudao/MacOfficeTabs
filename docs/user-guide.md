## 1. 工具用途与使用范围

MacOfficeTabs 为 Microsoft Office for Mac 的原生文档窗口提供一个独立的浮动标签栏。打开多个文档时，可以通过标签切换窗口、调整标签顺序，并请求 Office 关闭指定文档。

目前支持识别的应用为：

| 应用 | 标签管理对象 |
|---|---|
| Microsoft Word | 文档窗口 |
| Microsoft Excel | 工作簿相关文档窗口 |
| Microsoft PowerPoint | 演示文稿编辑窗口 |

它保留 Office 原有的独立窗口布局，不把文档嵌入一个新的主窗口。只显示**当前处于前台的 Office 应用**的标签：Word 在前台时显示 Word 文档，切到 Excel 后显示 Excel 文档，切到浏览器等其他应用后隐藏。

当前版本没有跨应用混合分组、正文编辑、自动保存、自动处理保存提示或标签顺序跨工具重启恢复功能。PowerPoint 幻灯片放映窗口不作为标准文档编辑窗口管理。

日常功能使用 macOS 辅助功能接口读取窗口和菜单信息、核验焦点并请求切换或原生关闭，不读取文档正文。项目另有显式调用的 Word 自动化研究入口，日常使用无需运行，也无需因此开启 Apple Events 自动化权限。

## 2. 环境要求

| 项目 | 要求或当前事实 |
|---|---|
| 操作系统最低声明 | macOS 13.0 |
| 当前实机验证环境 | Apple Silicon（arm64）、macOS 27.0.1（26A434） |
| 当前实机 Office 版本 | Word、Excel、PowerPoint 16.113.4 |
| Office 安装 | 自行安装并能够正常打开对应文档 |
| 必要权限 | MacOfficeTabs 的辅助功能控制权限 |
| 源码构建 | 支持当前 macOS SDK 的 Xcode 或 Command Line Tools；项目 Swift 工具版本声明为 5.9 |
| 第三方项目依赖 | 无 |

最低系统声明表示构建目标，不能据此认定所有 macOS 13 及以上版本均已验证兼容。Intel、其他 macOS / Office 版本和多物理屏尚缺实机验证。

## 3. 首次启动与授权

### 3.1 启动已有应用包

从源码构建后会生成应用包：

```text
build/MacOfficeTabs.app
```

在 Finder 中打开项目的 `build` 文件夹，双击 `MacOfficeTabs.app`。也可在项目根目录执行：

```sh
open build/MacOfficeTabs.app
```

启动后会出现“Office 窗口诊断”窗口，其中显示版本、权限状态和候选窗口列表。当前版本应显示 `0.2.9 (18)`。

首次使用推荐顺序：**准备或构建应用包 → 启动 → 授权 → 打开 Office 文档并切到前台 → 点击标签核验**。

### 3.2 开启辅助功能权限

1. 在诊断窗口点击“打开辅助功能设置”。
2. 找到允许应用控制电脑的权限页面。已测 macOS 27 页面名为“设备控制和数据访问”；旧版系统通常位于“隐私与安全性 → 辅助功能”。不要误选用于视觉、听觉等辅助设置的“无障碍”页面。
3. 点击“＋”，选择本项目的 `build/MacOfficeTabs.app`。
4. 启用该应用对应的开关。如系统要求身份验证，按系统提示完成。
5. 返回工具，点击“刷新”，检查是否仍提示未获得权限。
6. 打开 Word、Excel 或 PowerPoint 文档，并把文档编辑窗口切到前台。

系统权限开关开启，不代表当前运行的签名身份必然已经获准。以工具实际诊断为准；如果仍显示“未获得辅助功能权限”，按[权限排查](#9-常见问题与排查)处理。

### 3.3 完成第一次标签切换

建议用两个可辨认的测试文档熟悉操作：

1. 在同一个 Office 应用中打开两个文档。
2. 将任一文档置于前台，等待窗口内部顶部出现浮动标签栏。
3. 点击另一个标签的**标题区域**，确认目标文档成为当前编辑窗口。
4. 如当前标签的“×”仍不可用，先切到另一个标签，再切回这个标签完成焦点关联。

只有一个文档时，点击标签后，工具在菜单候选与真实窗口均唯一且核验通过的条件下也可完成关联；无法确认时仍保留关闭禁用状态。

初次操作可在测试副本中输入少量文字并撤销，确认键盘输入进入预期文档。

## 4. 日常使用标签栏

### 4.1 标签栏的位置与显示条件

普通窗口、铺满窗口和原生全屏均使用同一布局：**当前焦点文档窗口内部顶部居中**。标签栏为窄浮条，避开系统菜单和刘海安全区，但可能覆盖少量 Office 工具栏。

移动或缩放文档窗口后，工具会根据窗口位置重新计算浮条位置。当前没有可设置的固定位置、底部布局或浮条自由拖动入口。

以下情况下浮条会隐藏：

- 当前前台应用不是 Word、Excel 或 PowerPoint。
- 当前应用的标签栏已在设置中关闭。
- 文档窗口最小化、不可见，或可见空间太小。
- 当前没有可确认的标准窗口焦点。
- Office 出现保存提示等模态界面，或工具无法确认安全状态。
- 权限被拒绝、扫描失败或正在核验一次控制操作。

打开工具设置或诊断窗口时，Office 暂时失去前台位置，浮条隐藏是预期行为。返回 Office 文档后再查看是否恢复。

### 4.2 识别标签

标签显示“文档标题 · 短 ID”，例如：

```text
会议纪要.docx · 4A4AAB87
```

当前已核验为焦点的标签使用蓝色文字和较粗字重。鼠标停留在标题上可以查看完整标题、短 ID 和操作提示；长标题在标签中可能从中间省略。

短 ID 是运行期对象标识，用于区分同名对象，不是文件路径或永久文件编号。文档关闭后重开、Office 重启或工具重新启动后，ID 可能改变。不要仅根据标题判断两个同名标签属于同一个文件。

Excel 是否允许同时打开两个同名工作簿由 Excel 决定；MacOfficeTabs 不绕过 Office 原有限制。

### 4.3 切换文档

点击目标标签的标题即可请求切换。工具会核验前台 Office 进程与实际窗口焦点，无法确认时不会把请求视为成功。

标签栏采用不成为键盘焦点窗口的面板，设计目标是在切换后继续直接编辑 Office 文档。若实际输入未进入预期文档，先停止输入，核对当前窗口和诊断信息。

### 4.4 查看更多标签

文档较多时，标签栏内部可横向滚动。使用触控板横向滚动或横向滚动条查看右侧标签。浮条不会为了容纳所有标签而无限扩宽。

### 4.5 调整顺序

在标签**标题区域**按住鼠标，左右拖动，松开后调整排序。不要从“×”上开始拖动。

Word、Excel、PowerPoint 各自维护运行期顺序。快捷键按拖动后的视觉顺序循环；该顺序不写入持久化设置，退出工具后不保证恢复。Office 进程退出后，其标签顺序也会重置。

## 5. 关闭文档与保存提示

### 5.1 为什么“×”有时不可点击

标签候选可能来自 Office 的窗口菜单，初次发现时尚未与真实窗口建立可靠关联。为避免关闭错误文档，关联前“×”禁用。

先点击目标标签标题。多文档情况下，如果点击当前标签没有形成可核验的焦点变化，先切到另一标签，再返回目标标签。核验通过后，“×”才可用。始终无法确认时，可在 Office 中使用原生关闭操作。

### 5.2 正确关闭流程

1. 确认标题、短 ID 和当前文档内容。
2. 点击可用的“×”。
3. MacOfficeTabs 将关闭请求交给 Office 原生关闭命令。
4. 如果 Office 弹出保存提示，由你选择保存、放弃修改或取消；实际按钮名称随应用和版本变化。
5. 真正关闭的对象在后续发现中移除；如果选择取消，文档保留，安全状态恢复后浮条重新显示。

出现保存提示时，浮条和快捷键会暂停，防止绕过模态界面。提示消失后若浮条没有恢复，先将文档窗口置前台，再查看诊断。

**关闭未保存文档前，请仔细检查 Office 的提示。** 工具不会替你自动保存或选择“放弃修改”；Office 是否需要提示仍由其自身文档状态决定。

“退出 MacOfficeTabs”只退出工具，和标签“×”关闭 Office 文档是两个不同操作。

## 6. 设置与快捷键

### 6.1 打开设置

将 MacOfficeTabs 切到前台，在 macOS 顶部应用菜单选择：

```text
MacOfficeTabs → 设置…
```

工具前台时也可按 `Command + ,`。

### 6.2 设置项与默认值

| 设置项 | 首次使用默认值 | 作用 |
|---|---|---|
| 显示标签栏：Word | 开启 | 控制 Word 浮条显示 |
| 显示标签栏：Excel | 开启 | 控制 Excel 浮条显示 |
| 显示标签栏：PowerPoint | 开启 | 控制 PowerPoint 浮条显示 |
| 启用 ⌃⌥⌘←/→ 切换当前应用标签 | 关闭 | 允许在符合条件时注册两个切换组合 |
| 登录时启动 MacOfficeTabs | 默认不注册 | 由 macOS 管理登录启动服务 |

三应用标签开关和快捷键开关会保存到用户偏好，下次启动继续使用。关闭某应用标签不会关闭该应用或文档，也不会影响其他应用的标签设置；该应用的切换快捷键同时不再满足启用条件。

### 6.3 使用切换快捷键

先在设置中勾选快捷键开关，再返回 Office，点击标签完成当前位置的真实焦点关联。

| 快捷键 | 动作 |
|---|---|
| `Control + Option + Command + ←`（⌃⌥⌘←） | 切换到当前应用视觉顺序中的上一个标签 |
| `Control + Option + Command + →`（⌃⌥⌘→） | 切换到当前应用视觉顺序中的下一个标签 |

到首尾时循环。只有一个标签时不会切换；当前标签未建立焦点关联时也不会循环。当前版本没有修改这两个组合的设置入口。

快捷键仅在开关开启、对应标签栏开启、Office 在前台且窗口状态安全时注册。离开 Office、进入模态界面、扫描或控制状态不安全时会注销；它不用于在 Word 与 Excel 等不同应用之间切换。

### 6.4 快捷键冲突与重试

注册失败时，设置状态会提示类似：

```text
快捷键注册失败或冲突（-9878）；两项均未占用。关闭后重新开启可重试。
```

错误码可能不同。如果任一组合失败，工具撤回整组，不保留另一组合。失败状态不会在外部占用释放后自动重试。

处理步骤：

1. 检查其他快捷键工具是否占用该组合，释放冲突组合。
2. 在 MacOfficeTabs 设置中取消勾选快捷键，再重新勾选。
3. 返回 Office，确认标签已关联且无对话框，再试左右切换。

当前使用 Carbon 独占注册，已验证真实外部独占冲突的回滚与恢复；部分非独占共享组合不能保证被检测。出现双重响应时，可关闭 MacOfficeTabs 快捷键并继续使用鼠标标签。

## 7. 登录时启动

登录启动默认不注册，需要你在设置中显式勾选“登录时启动 MacOfficeTabs”。工具使用 macOS 的登录服务管理机制，界面读取系统当前状态。

| 设置中显示的系统状态 | 含义与处理 |
|---|---|
| 已启用 | 系统报告登录服务已启用 |
| 等待你在登录项设置中批准 | 点击“打开登录项设置”，在系统页面完成批准 |
| 未注册（默认关闭） | 尚未注册或已注销，登录启动开关关闭 |
| 尚未找到服务 | 当前系统未找到对应服务；可显式开启后检查注册结果 |
| 操作失败：… | 本次注册或注销失败，保留错误描述供排查 |

关闭登录启动时，取消勾选，并检查系统状态是否变为“未注册”。该操作不会立即退出正在运行的工具。

当前已有本机注册和注销成功的证据，**实际注销账户后重新登录并自动启动尚未验证**。“已启用”不能直接作为真实登录启动已通过的证明。现有开发包位于项目构建路径，更新或更换位置后应重新检查系统状态。

## 8. 窗口诊断与问题反馈

### 8.1 打开诊断窗口

在应用菜单选择“显示窗口诊断”。窗口显示当前路由应用的候选标签、权限和最近状态；首次启动默认从 Word 路由开始，切换前台 Office 应用后更新对应对象。

| 界面内容 | 用途 |
|---|---|
| 版本与构建号 | 确认当前运行候选 |
| 权限 / 扫描状态 | 查看权限拒绝、Office 未运行、扫描失败或候选数量 |
| 窗口标题 | 对照 Office 中的文档标题 |
| 运行时 ID | 区分同名候选，不表示永久文件身份 |
| AX 焦点 | 查看是否已核验为当前窗口 |
| 最小化 | 查看窗口是否最小化；未关联时可能为未知 |
| 几何 / 文档关联 | 区分菜单候选与已核验的 AX 窗口关联 |
| 最近事件及 panel 信息 | 辅助判断浮条显示、隐藏及前台状态 |

标签数量和标准窗口数量不一定相等，尤其在全屏或存在尚未关联的菜单对象时。数量不同本身不代表文档被丢失。

### 8.2 诊断按钮

- **刷新**：重新请求扫描当前路由应用。
- **激活并核验选中窗口**：先在列表选中目标，再请求激活并核验；该按钮本身不关闭文档。
- **打开辅助功能设置**：进入系统权限页。
- **复制诊断（含标题）**：复制状态、窗口标识、标题和最近事件到剪贴板。

诊断窗口中的部分说明沿用早期诊断用途；日常标签栏的“×”确实会请求关闭文档，应以本手册的关闭流程和具体操作入口为准。

浮条诊断中的常见 `reason`：

| reason | 含义 |
|---|---|
| `internalTop` | 已按窗口内部顶部规则显示 |
| `officeNotFrontmost` | Office 当前不在前台 |
| `disabled` | 对应标签栏被关闭 |
| `scanOrActionUnsafe` | 扫描或控制状态不满足条件 |
| `noStandardFocus` | 没有可确认的标准焦点窗口 |
| `minimizedOrUnknown` | 已最小化或最小化状态未知 |
| `modalOrUnknown` | 模态状态阻断或安全状态未知 |
| `geometryUnknown` | 缺少窗口位置或屏幕信息 |
| `noInternalSafeSpace` | 窗口可见空间不足以安全放置浮条 |

打开诊断时 Office 已失去前台，`visible=false` 或 `officeNotFrontmost` 可能正是打开诊断引起的正常变化；结合问题发生时的场景判断。

### 8.3 提交有用的问题信息

记录工具版本、macOS 与 Office 版本、出问题的应用、普通/铺满/全屏模式、屏幕数量、具体步骤、预期结果和实际结果。涉及关闭时，补充是否有未保存修改、是否出现保存提示、选择了哪个按钮。

可附上“复制诊断”的内容。**诊断包含文档标题和运行时信息，分享前检查并删去敏感名称。** 不必提供文档正文，优先使用测试副本复现。

## 9. 常见问题与排查

| 问题 | 优先检查和处理 |
|---|---|
| 启动后没有标签栏 | 打开真实 Office 文档并切到前台；诊断或设置前台时浮条会隐藏。检查辅助功能权限与对应应用标签开关。 |
| 系统开关已开，工具仍说未授权 | 核对授权对象是否为当前 `build/MacOfficeTabs.app`。退出工具，在权限页移除旧条目并添加当前包、启用，再启动检查；更换签名或使用 ad-hoc 构建可能需要重新授权。 |
| 标签突然隐藏 | 检查保存提示、其他对话框、最小化、极小窗口和前台应用。处理提示后回到文档；不要强制绕过模态保护。 |
| 标签标题可点，“×”灰色 | 先点击标题完成关联；多文档时先切另一个再回来。工具无法确认身份时保持关闭禁用。 |
| 单文档“×”仍灰色 | 点击标题触发核验；唯一候选 / 唯一窗口条件不满足或安全状态未知时不会关联。可直接在 Office 中关闭。 |
| 快捷键没有响应 | 检查开关、对应标签栏、是否至少两个标签、Office 是否前台及当前焦点是否关联；查看是否注册失败。 |
| 冲突程序已退出，快捷键仍不能用 | 关闭快捷键开关后重新开启，返回 Office 重试；失败不会自动恢复。 |
| 两个同名标签分不清 | 查看短 ID，并点击后对照实际内容；鼠标悬停查看完整标题。不要把短 ID 当作文件路径。 |
| Excel 拒绝打开第二个同名工作簿 | 属于 Excel 原生限制；工具不会绕过。使用可打开的不同名称测试副本验证切换。 |
| 保存提示取消后没有浮条 | 确认对话框真正关闭、文档仍在且置前台；查看安全状态。必要时只重启工具，保留 Office 中的未保存文档。 |
| 列表显示扫描失败 | 工具可能保留过期快照并禁止操作。检查 Office 响应、权限和模态界面，处理后刷新；持续失败时复制诊断。 |
| 放映 PowerPoint 时没有编辑标签栏 | 放映窗口不作为标准编辑窗口管理；返回演示文稿编辑窗口。 |
| 多屏或其他系统上位置异常 | 当前缺对应实机验证。记录屏幕布局、窗口模式和诊断，不根据单屏结果认定多屏兼容。 |
| 勾选登录启动但无法确认生效 | 查看系统状态，必要时打开登录项设置批准；实际重新登录目前未验。 |

推荐恢复顺序：处理 Office 对话框 → 将文档置前台 → 检查权限和开关 → 诊断刷新 → 只退出并重新启动 MacOfficeTabs。不要为了排查直接退出有未保存内容的 Office。

## 10. 退出、更新与停止使用

### 10.1 正常退出

在 MacOfficeTabs 应用菜单选择“退出 MacOfficeTabs”，或在工具前台按 `Command + Q`。工具清理浮条和注册的快捷键，Office 继续运行。

当前代码在最后一个应用窗口关闭后会退出：不要把关闭诊断窗口的红色按钮当作“后台常驻”入口。需要暂时收起诊断时，可最小化，或直接切回 Office。

### 10.2 更新本地构建

1. 从工具菜单退出 MacOfficeTabs，Office 可保持打开。
2. 按下一节重新构建应用包。
3. 启动新包，在诊断窗口检查版本和构建号。
4. 检查权限、三应用标签设置以及可选快捷键 / 登录启动状态。

保留同一项目开发签名身份有助于沿用辅助功能授权；更换证书、签名方式或包路径后需核对权限。当前没有自动更新或正式安装向导。

### 10.3 停止使用

如不再使用，先关闭登录启动并核对注销状态，再退出工具。可在系统权限页撤销 MacOfficeTabs 的辅助功能权限；其他应用的权限无需变更。

确认不再需要后可通过 Finder 移除该应用包。移除应用包不等于删除源码、用户偏好或项目开发签名资料；保留源码和签名资料可供以后重建。

## 11. 开发者构建与命令行诊断

本节适用于从源码运行或协助排查的人。以下命令均在项目根目录执行。

### 11.1 构建应用

```sh
swift test
bash scripts/build-app.sh
open build/MacOfficeTabs.app
```

`swift test` 执行核心逻辑测试；构建脚本执行 release 编译、组装 `.app`、签名并进行严格签名验证。产物仍为 `build/MacOfficeTabs.app`。核心测试不能替代真实 Office 的切换、编辑和保存提示验证。

构建错误时先核对 `swift --version`、`xcode-select -p` 和当前 SDK。若工具链缓存写入受运行宿主的沙箱阻止，应通过宿主权限机制允许运行构建；项目不需要因此下载第三方依赖。

### 11.2 设置项目专用开发签名

新机器如需固定本地签名身份，可先运行：

```sh
bash scripts/setup-dev-signing.sh
bash scripts/build-app.sh
```

脚本在项目 `.dev-signing/` 中准备专用证书、私钥、密码和开发钥匙串，不修改系统根信任、登录钥匙串或默认钥匙串。没有该配置时，构建脚本回退到 ad-hoc 签名。

**不要分享、上传或提交 `.dev-signing/` 内容。** 项目专用开发签名不是发行用 Developer ID 签名，也不包含公证。生成或更换签名后，按首次授权步骤核对权限。

### 11.3 只读命令行诊断

推荐通过 LaunchServices 启动应用包，以接近已授权 GUI 的启动上下文。示例：

```sh
open -n -a build/MacOfficeTabs.app --stdout /tmp/MacOfficeTabs-diagnose-word.json --args --diagnose com.microsoft.Word
open -n -a build/MacOfficeTabs.app --stdout /tmp/MacOfficeTabs-diagnose-excel.json --args --diagnose com.microsoft.Excel
open -n -a build/MacOfficeTabs.app --stdout /tmp/MacOfficeTabs-diagnose-powerpoint.json --args --diagnose com.microsoft.Powerpoint
```

每次启动一个独立诊断进程，输出写入指定 JSON 文件；命令返回后，输出可能仍需等待进程完成再读取。`--diagnose` 不传应用标识时默认诊断 Word。PowerPoint 的标识拼写为 `com.microsoft.Powerpoint`。

诊断读取窗口、菜单与屏幕信息，不执行标签切换或关闭，不主动弹出授权申请。JSON 中的 `tabs` 包含标题，输出文件分享前同样需要检查。

| JSON `status` | 含义 | 诊断进程退出码 |
|---|---|---|
| `ok` | 扫描成功；仍需看 `officeRunning` 和候选数量 | 0 |
| `permissionRequired` | 当前诊断身份没有辅助功能权限 | 2 |
| `scanFailed` | 扫描失败 | 3 |

参数不合法时进程退出码为 64。`open` 本身的返回码不等于诊断子进程退出码，应读取 JSON 判断结果。

直接从终端运行包内二进制可能受调用方权限上下文影响，不能只凭这种启动方式失败就认定正常 GUI 未授权。独立诊断进程产生的 UUID 也不能拿来证明已运行 GUI 内文档身份发生变化。

批量切换与快捷键占用试验脚本属于研发验收工具，部分会真实切换文档或占用快捷键。日常排查无需运行；需专项验证时参见 [贡献与测试说明](../CONTRIBUTING.md)。
